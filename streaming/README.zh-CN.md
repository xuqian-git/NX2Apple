# NXStream 原型

这是 xuqian-git/NX2Apple 的实验性局域网串流分支。游戏仍在 iPhone 上运行，安卓车机或电视接收画面和声音。

## 当前范围

- H.264 硬件编码，自动匹配接收端尺寸和解码能力，也支持手动选择，最高发送节奏 60 fps。
- NVN 游戏最终纹理接入，默认不在手机上显示游戏画面，保留前台运行。锁屏或退到后台会暂停。
- 输出尺寸与游戏内部原生渲染尺寸不同。串流模块按所选尺寸缩放，游戏原生分辨率由其 profile 和 DM_RENDER_SCALE 决定，不能保证所有游戏原生 1620p。
- PCM 48 kHz，保留游戏实际输出的立体声或六声道。协议预留 8/12 声道，但不会把 5.1 伪装成原生 7.1.4，也不生成 Dolby Atmos。
- 安卓原生硬件解码和 Surface 显示。音频只有在系统报告可用的多声道直通能力时才尝试相应 AudioTrack，否则混成立体声。原车 DSP 私有接口未接入。
- IPv4 UDP，同一可信局域网。自动发现和媒体传输不提供认证或加密。不要做公网端口映射。

## 安装和连接

1. 更新安卓 NXStream 接收端，打开后自动开始接收。不需要输入 IP 或 token。
2. 用本 fork 最新 Mac 版更新 iOS 外壳，并重新构建游戏 framework。旧版本引擎不认识自动分辨率参数，仅更新安卓端不够。
3. 手机、车机连接同一局域网。可以手机开热点、车机开热点，也可以同时连接第三方热点。
4. 打开 iPhone App「设置 → 投屏」，允许“本地网络”权限，等待自动扫描，点选接收端，再打开「投屏到安卓设备」。
5. 分辨率默认「自动」，按接收端实际屏幕尺寸和硬件解码能力选择。无需手抄配置，手动下拉列表只列出接收端上报的可用尺寸。
6. 启动游戏。修改接收端、分辨率或「隐藏 iPhone 游戏画面」后，重新启动游戏生效。保持应用前台，不锁屏。手柄连接 iPhone。

媒体固定使用 UDP 48000，设备发现固定使用 UDP 48001，并使用 Bonjour 公布服务。扫描兼容热点屏蔽组播但允许设备间单播的情况。热点开启客户端隔离时，任何直接串流都无法互通，需要关闭隔离。实际三种热点设备组合尚需真机测试。

目前使用 IPv4。普通家庭网和热点会扫描所在子网，大于 1024 地址的网络通过 Bonjour、手机所在 /24 网段及子网首个主机地址发现，不遍历整个大型企业网。切换热点后重新进入投屏设置扫描并选择设备。

自动输出不再局限于三档，当前支持偶数宽高、单边最大 4096、总像素不超过 4096×2160 的 H.264 输出。接收端先报告实际尺寸及降档尺寸，iPhone 硬件编码器依次尝试。游戏画面保持比例，必要时留黑边。输出分辨率不等于游戏内部原生渲染分辨率。

## 延迟与卡顿统计

安卓接收端画面左下角显示统计浮层，可在控制面板「Show latency and stall statistics on the picture」开关。每秒一行同样写入 logcat（`adb logcat -s NXStats`），卡顿原因发生时另记一行：

- `E2E`：iPhone 采集帧到车机解码输出的时间，拆为 采集→收齐（含 GPU 拷贝、编码、网络）、解码队列等待、解码。需要新版 iPhone 端回应时钟探测，旧版显示 n/a。不含车机合成到屏幕的最后一段。
- `RTT`、收到/显示帧率、码率、网络丢包（发送端发出包数与接收端收到包数之差）。
- `freezes`：两帧显示间隔超过 100 ms 的次数和最长间隔。logcat 中 `FREEZE` 行附带之前最近一次原因：`INCOMPLETE`（分片未收齐）、`SEQ_GAP`、`QUEUE_OVERFLOW`、`DECODER_BUSY`、`SEND_ERROR`（iPhone 发送失败）。
- `sender`：iPhone 端发送失败次数和 errno、编码器忙时跳过的帧、采集到编码完成的最长时间。
- logcat 另有音频字段：每秒播放帧数（正常约 48000）、最大积压、丢块、音轨重建次数，以及音频焦点变化（`AUDIO_FOCUS`）。

接收端开始收到声音时申请音频焦点，车机正在播放的音乐会暂停，关闭 NXStream 后释放。解码器未声明标准低延迟能力时，接收端设置高通、联发科、三星的厂商低延迟参数。高通车机（SA8155）实测不设置时每个关键帧卡顿 200–350 ms，设置后解码约 8 ms，端到端约 25 ms（Mac 发送端测试，不含屏幕合成）。

## 验证与限制

已进行的自动化检查会记录在 Actions：协议乱序/重复/超时/恶意长度测试，安卓 APK 编译，iOS 发送模块 SDK 编译检查，修改后的完整 macOS 游戏 host 编译，Mac launcher 构建和打包。
本机另有真实 Metal + VideoToolbox 回环测试，三档分辨率 H.264 解码成功，六声道 PCM 保持声道数据。独立 Android 12 模拟器已安装并接收三档分辨率的测试画面，验证重连和六声道到立体声降级，但模拟器不代表车机解码性能。生产 iOS 工程也通过合成模块的无签名编译链接测试。新增设置通过 iPhone 模拟器界面测试，Bonjour 自动发现通过真实 UDP 请求响应测试，Android 12 模拟器也验证了接收端自动响应和 1280×640 输出。自动尺寸另验证了 2560×1600 和 1280×800。

尚未证明：具体 iPhone 的游戏内表现、车机硬件解码/多声道实际路由、长时间热稳定性、音画同步漂移、端到端延迟。没有游戏内容的 Actions 不进行实际游戏测试。不将编译成功视为超低延迟达标。

当前只接 NVN 最终呈现路径，不承诺 Vulkan/OpenGL 游戏。SDR 首版，不承诺 HDR 色彩。音频抓取一个最终输出流，多输出设备并行混音尚未实现。原型不支持安卓端回传手柄输入、动态码率和网络拥塞自适应。网络丢包会请求 IDR，视频队列和音频队列有上限，严重拥塞应降低分辨率。

## 构建与维护

- `streaming/check.sh`：协议测试和 iOS 模块编译检查。
- `gradle -p streaming/android assembleDebug`：安卓 APK，需 Gradle 8.13、JDK 17+、Android SDK 35。
- `python3 tools/engine.py sync` 后用 `tools/engine.py tree --out <目录>` 导出引擎，再运行 `python3 streaming/overlay.py <目录>`。overlay 对上游接入点做精确匹配，不匹配就失败，不静默跳过。
- `streaming/build_mac.sh <绝对输出目录>` 在一次性 checkout 中构建 Mac app（会调整此 checkout 的启动器编译输入）。
- Fork 工作流每日新加坡时间 04:30 检查 LNPANDY/NX2Apple main。合并候选先构建验证，全部成功才合入 fork main，冲突或构建失败保留 main。定时触发时间可能被 GitHub 延后。
- Actions 安卓产物使用此 fork 专用的稳定签名密钥，可覆盖安装后续同签名构建。本地 assembleDebug 是另一调试签名，不可直接覆盖 release 版。
